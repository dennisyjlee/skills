# Sharing: set it up for feedback

A prototype that only works when you're driving it can't collect feedback. Make it self-explanatory for someone clicking it alone.

## Built-in controls (the kit has these)
- **Desktop / Mobile** toggle, and a deep link per mode.
- **Captions:** a dark pill at the bottom with one line per story beat. It changes with the state, so an async viewer knows what they're looking at.
- **Tap hints:** a soft pulsing ring on the next target. Toggleable, off for people who want to explore.
- **Restart:** back to the first state without reloading.

## Share it
- Publish a link, not a file. One URL that stays the same across updates, so earlier feedback threads still point to the latest version.
- Say what kind of feedback you want: the flow, the copy, or the feel. Otherwise you get pixel notes on an idea that isn't settled.

## Capture what you hear
- Write every note down the same day in the feedback log: what was said, what changed, and the rule it becomes (see `feedback-log.md`).
- A note about one screen is a fix. A note that would apply to the next prototype too is a rule. Put rules in this skill.

## When to switch to video
- The audience can't click: a slide, a site tile, an email, a case study.
- The story needs a specific path and pacing that a free click-through won't give.
- The same prototype becomes the video source. See `pacing.md`.
